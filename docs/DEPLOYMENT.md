# Deployment

Target: **Cloudflare Workers** (TanStack Start SSR via Nitro `cloudflare-module` preset).
The Worker serves SSR documents and server functions; `dist/client` is uploaded as Worker
static assets (`ASSETS` binding).

## Build

```bash
bun install
bun run build      # Vite + Nitro edge worker + PWA precache
```

Output:

| Path | Contents |
| --- | --- |
| `dist/client` | Client bundle, `sw.js` (~158 precache entries, ~1.5 MB), `_headers` |
| `dist/server` | Worker entry `index.mjs` + code-split chunks |
| `dist/server/wrangler.json` | Generated deploy config (root `wrangler.jsonc` merged in) |

Any router-generator warning is a blocker — fix before shipping.

## Wrangler configuration

`wrangler.jsonc` at the repo root is the hand-authored source: worker `name`,
`compatibility_date`, `nodejs_compat`, observability. Nitro merges it into
`dist/server/wrangler.json` on every build and owns `main`, `assets`, `no_bundle`, `rules`.
**Never edit `dist/server/wrangler.json`** — it is regenerated.

## Deploy

```bash
bun run deploy          # wrangler deploy --config dist/server/wrangler.json
bun run preview:worker  # wrangler dev  --config dist/server/wrangler.json (local edge emulation)
```

CI: `.github/workflows/deploy-production.yml` runs on push to `main` (and `workflow_dispatch`):
install → typecheck → lint → build → `cloudflare/wrangler-action@v3`. Build and deploy happen in
the same job on purpose — `VITE_*` values are inlined at build time, so client and worker must
come from one build.

## Environment variables

### Build time (GitHub Actions repo/environment secrets — inlined into the bundle)

| Name | Required | Purpose |
| --- | --- | --- |
| `VITE_SUPABASE_URL` | yes | Supabase project URL |
| `VITE_SUPABASE_ANON_KEY` | yes | Supabase publishable key |
| `VITE_CLOUDINARY_CLOUD_NAME` | no | Media delivery (degrades if unset) |
| `VITE_CLOUDINARY_UPLOAD_PRESET` | no | Unsigned upload preset |

### Worker runtime (Cloudflare, set via `wrangler secret put` or the dashboard)

| Name | Required | Purpose |
| --- | --- | --- |
| `SUPABASE_URL` | yes | Read by `src/server.ts` to build the CSP `connect-src` |

### GitHub Actions deploy credentials

| Name | Purpose |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | Token with **Workers Scripts: Edit** (+ Workers R2/KV only if later used) |
| `CLOUDFLARE_ACCOUNT_ID` | Target Cloudflare account |

## Required Cloudflare settings

1. Workers & Pages → the Worker `hangeul-lpk` (created on first deploy).
2. `nodejs_compat` compatibility flag — already in `wrangler.jsonc`.
3. Static assets enabled via the `ASSETS` binding (generated by Nitro; nothing to click).
4. Observability/logs enabled — already in `wrangler.jsonc`.
5. Custom domain: Workers → Settings → Domains & Routes → add the production hostname.
6. Keep Cloudflare's "Auto Minify"/Rocket Loader **off** — they conflict with the SSR CSP.

## Pre-deploy checklist

1. `bun run typecheck` — PASS.
2. `bun run lint` — 0 errors.
3. `bun run build` — PASS, no warnings.
4. `dist/server/wrangler.json` shows the expected `name` and `nodejs_compat`.
5. Build secrets present in the GitHub `production` environment (table above).
6. `SUPABASE_URL` set on the Worker.
7. `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID` set in GitHub secrets.
8. Database migrations applied; linter shows only the four accepted `SECURITY DEFINER` warnings.
9. Cloudinary cloud + unsigned upload preset configured (or accepted as degraded).
10. Smoke test on `bun run preview:worker`: sign in → open a lesson → run one exam attempt.

## Post-deploy verification

- Load the production URL; confirm `content-security-policy`, `strict-transport-security`,
  `x-frame-options: DENY`.
- Confirm SSR: view-source shows rendered HTML, not an empty shell.
- Exercise one server function (sign-in) and check `wrangler tail` for errors.
- Install the PWA on Android Chrome and confirm the offline shell renders when offline.
- Confirm `audit_logs` receives a new entry after an admin action.

## Rollback checklist

1. **Worker**: `wrangler rollback --config dist/server/wrangler.json` (or Deployments →
   previous version → Rollback in the dashboard). Instant, stateless.
2. **Database**: forward-fix only. Never drop a column or table to roll back; ship a corrective
   migration. Snapshots and audit logs are append-only and must not be rewritten.
3. **Secrets**: if a rotated key caused the incident, restore the previous value; the Worker
   picks it up on the next request after a redeploy.
4. **PWA**: if a bad service worker shipped, deploy a kill-switch worker at `/sw.js` for one
   release cycle so installed clients evict the stale registration.
5. Re-run the post-deploy verification list before declaring the rollback complete.

## Remaining manual steps

- Create the Cloudflare API token and add both Cloudflare secrets to GitHub.
- Add the four `VITE_*` build secrets to the GitHub `production` environment.
- Run `wrangler secret put SUPABASE_URL` once (or after the first deploy creates the Worker).
- Attach the custom domain and re-check headers.
